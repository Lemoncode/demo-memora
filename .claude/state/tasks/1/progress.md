## Decision log

- **T1 — the pnpm migration was low-risk, not high-risk.** The Orchestrator flagged
  that reinstalling `@lemoncode/lemony` under pnpm could break the hooks this session
  depends on. Checked first: the package resolves from the **public npm registry**
  (`registry.npmjs.org`), not GitHub Packages as `lemony.sh`'s comment suggests, so no
  auth was involved. After `pnpm install`, `node_modules/.bin/lemony` exists and
  `.claude/hooks/lib/lemony.sh --version` prints `0.10.0` (R5 proven). No discovery
  needed.
- **T4 — `.prettierignore` also excludes two harness files that live outside
  `.claude/`.** R11 enumerates `node_modules`, `.claude/`, `pnpm-lock.yaml`, build
  outputs and caches, but the installer also drops `harness.config.schema.json` (repo
  root) and `docs/playbooks/README.md`, and Prettier wanted to reformat both. Both are
  regenerated by `lemony repair`/`update`, which is exactly the failure R11 exists to
  prevent ("a harness vendor update can never fail the format gate"). Added them to the
  ignore list — faithful to R11's rationale, a small extension of its literal list.
  **Flagged for the reviewer.**
- **T3 — dropped `exactOptionalPropertyTypes` from `tsconfig.base.json`.** R8 requires
  `strict: true`; I had also added this option, which is high-friction against React and
  third-party prop types for little value here. The base keeps `strict` plus
  `noUncheckedIndexedAccess`, `noImplicitOverride`, `noFallthroughCasesInSwitch`,
  `verbatimModuleSyntax` and `isolatedModules`.
- **T5 — `apps/web` was authored by hand, not left as CLI output.** The official
  scaffolder (`create-start-app` 0.59.45, run in a scratchpad probe only) was used to
  learn the current API shape, then discarded. Its output could not be used as-is: its
  `styles.css` ships a complete custom visual direction (bespoke palette, a remote
  Google Fonts `@import`, gradients, `.island-shell`/`.feature-card` classes) and
  `components.json` defaults to base colour **`zinc`**. R13 requires `neutral` and R16
  plus the human's gate instruction require default tokens only with no visual-direction
  decisions. Authoring the app directly satisfies R18 by construction rather than by
  pruning, and keeps the remote font request (a hermeticity hazard) out of the repo.
- **T5 — the test config is a separate `vitest.config.ts`.** A `test` block inside
  `vite.config.ts` is no longer valid against Vite 8's `UserConfig` type (the typecheck
  gate caught it: `'test' does not exist in type 'UserConfigExport'`). design.md allows
  either shape. The split also keeps the Nitro/Start SSR plugins out of the smoke test,
  which is what makes it hermetic (R56).
- **T6 — the shadcn `neutral` token block was taken verbatim from the shadcn
  registry.** `shadcn add button card` installed the components but wrote **no** CSS
  variables, so `bg-card` / `bg-primary` would not have existed and the styling chain
  would have been silently broken. Fetched the canonical values from
  `https://ui.shadcn.com/r/colors/neutral.json` (`cssVarsV4`) and wrote them with the
  Tailwind v4 `@theme inline` wiring. **No invented values.** The full default set is
  kept, including the `.dark` block — those are shadcn's defaults and nothing in the app
  toggles them, so R16 (no switcher, no toggle, no custom palette) holds.
- **T6 — `shadcn add` left a missing dependency.** `button.tsx` imports `cva` from

- **T7 — the page component lives in `src/components/home-page.tsx`.** The spec file
  cannot sit in `src/routes/` (the TanStack route generator scans that directory), and

- **`routeTree.gen.ts` is committed, not gitignored.** CI runs `typecheck` before

  `./routeTree.gen`. It is Prettier-ignored (the file's own header says to exclude it

### Findings

**1. Advisory, headline — the destructive confirm's safe default has no regression test.**
`console-runner/src/main.ts:116` is `default: false, // Enter cancels (R48).` and that is
correct; the Implementer's real run recorded the `(y/N)` rendering, Enter cancelling, and
the seeded document intact. But flipping it to `default: true` — turning Enter from
*cancel* into *delete the database* — leaves the whole `console-runner` suite green, 7/7.
This is the only destructive operation in the delivery, in a group that declared
`[risk: data-loss]`, and its guard is held up by a one-off manual observation that does not
regress.

I did **not** reject on it, deliberately: the implementation meets R48, and the gap sits
inside `design.md`'s *human-approved* decision that the prompt layer is not tested
("testing it would mean driving a TTY"). Rejecting would overrule a decision the human
already signed at the spec gate. Cheapest closure if the human wants it closed, no TTY
needed: extract the confirm's options (or a `buildCleanConfirm(database)` factory) and
assert `default === false` and that the message names the database — roughly ten lines.

**2. Advisory — Ctrl+D at a prompt exits 13 with a Node warning, and it is undocumented.**
Reproduced independently: stdin EOF at the menu leaves
`Warning: Detected unsettled top-level await at console-runner/src/main.ts:146` and
`ELIFECYCLE Command failed with exit code 13`. R44 specifies Ctrl+C, which works
correctly, so this is *unspecified* rather than failing, and it is non-destructive — I
judge it acceptable to ship for a local maintenance tool. But it is **absent from the
record above**, and R58/R59 make `progress.md` the durable real-run evidence; the human
should know before signing. Noted here so it is no longer undocumented.

**3. Security, medium / hardening — the credential-less Mongo publishes on all interfaces.**
`docker-compose.yml:20` is `- '27017:27017'`, which binds `0.0.0.0`. On any shared or
untrusted network, every host on the LAN gets unauthenticated full read/write on every
database. The header comment warns against copying the file to a reachable environment,
but the default binding already makes the dev machine reachable. `'127.0.0.1:27017:27017'`
closes it and still satisfies R22's port publication and R28's
`mongodb://localhost:27017/memora`. Not a spec violation — R22's letter is met — so it is a
recommendation, not a block.
